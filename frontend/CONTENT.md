## Capability map

`lib/capabilities.ts` is the single source for "available / available with limits /
planned". Each entry names the module and test that proves it. Pages that render it:
`/product` (all groups), `/workflows` (integration group), home "Verified coverage"
(integration group), workspace setup page (planned items).

Verified against `docs/ROADMAP.md` status and `src/suncly` on 2026-10-04:

- Available: card fetch and hash; human approval of the contract; repeated runs with
  deterministic run keys; Runner credential isolation and redaction; budget and
  execution controls; Ed25519 signing and `suncly verify`; "What was NOT tested";
  report folder (result.json, transcripts, report.md, report.html); CLI.
- Available with limits: deterministic drafter (no model; skills without examples are
  not tested); deterministic judge only (no Layer 2); customer criteria are structural
  (`model_checks` make a run inconclusive); sandbox is a declaration, not verified;
  append-only store on files or Postgres (transcripts local); Policy engine flag-only;
  CI via the CLI only; comparison computed in the workspace from two bundles.
- Planned (named stages, no dates): probes (stage 4); Judge Layer 2 (stage 4);
  recording a human decision in the store (stage 5, OQ-P2); HTTP API (stage 5);
  CI adapter (stage 5); registry adapters (stage 6); object storage for transcripts.

## Workspace (`/app`)

Reads `result.json` + `transcripts/*.json` (format `suncly-result/1`,
`adapters/report/writer.py`). Verification mirrors `core/verify.py` (`lib/evidence/verify.ts`).
Comparison is computed in the browser (`lib/evidence/compare.ts`) and says so. Reviewer
notes are local and exported; the store has no human-decision interface yet (`API`
"Operations without an interface"). Commands are built from `cli/main.py` options
(`lib/cli.ts`). No run can be started from the browser (no HTTP API; `api.py` placeholder).
